# FOCUS — карта проекта

## Границы

Статический React / TypeScript frontend, https://todo.almistech.ru.
Репозиторий: https://github.com/AlmisAlex/almis-focus-todo.
Данные остаются в браузере. Серверной авторизации, API, облачной
синхронизации и сетевой отправки содержимого нет.

## Модули

- `domain/tasks.ts` — схема, валидация и детерминированные операции.
  `complete-occurrences` атомарно завершает задачу и создаёт один повтор.
  `completed` задаёт завершение, `workState` различает «План» и «В работе».
- `domain/taskDraft.ts` — черновик формы; последний набранный шаг входит в
  сохранение. Изменение статуса в черновике не завершает шаги до сохранения.
- `domain/workspace.ts` — операции проектов и переносов.
  `taskQueries.ts`, `calendar.ts`, `commandSearch.ts`, `workspaceRoute.ts`
  отвечают за выборки, даты, общий поиск и адрес раздела.
- `domain/planner.ts` — настройки, таймер по временным меткам и история;
  идентификатор сессии защищает повторное завершение.
- `domain/attachments.ts`, `boundedText.ts`, `demoFiles.ts` — ограничения
  файлов, ограниченное извлечение текста и безличные примеры.
- `storage/taskStorage.ts` — чтение форматов 1–4, миграция и резервирование.
  `taskRepository.ts` — очередь намерений и повтор поверх свежих данных.
  `taskTransfer.ts` и `workspaceBackup.ts` — локальный импорт/экспорт.
- `storage/plannerStorage.ts` — команды настроек/таймера и восстановление
  с полной копией исходных байтов. `attachmentStorage.ts` — IndexedDB.
- `hooks/useTasks.ts` и `usePlanner.ts` — React, Web Locks, события вкладок.
  `useAttachments.ts` — файловые операции и уведомление других вкладок.
- `useTaskOperations` — действия, ошибки и отмена; `useCaptureFlow` —
  быстрый ввод и редактор; `useDemoWorkspace` — примеры и повтор файлов.
  Позиция, фокус, дата и сочетания клавиш вынесены в отдельные hooks.
- `components/Workspace*` — навигация; `TaskComposer/Editor/Fields` —
  формы; `TaskItem/Board/Calendar` — представления одной модели.
  `FileLibrary/FilePreview/PdfDocument` — библиотека и локальный просмотр.
  `TaskBackup` — preview импорта, ошибки и повтор частично выполненной операции.
  `TaskActions` — единые действия задачи; у карточек и доски отдельная нижняя
  панель. `card-actions.css` — её компоновка и явные 1/2/3 колонки с собственной
  горизонтальной прокруткой на узком экране.
  `OfflineStatus` — установка, готовность оболочки и безопасное обновление.
- `App.tsx` — композиция, текущий раздел, фильтры и подключение сценариев.
  Бизнес-валидация и сериализация остаются вне компонентов.
- CSS разделён по областям. `ledger.css` содержит общие токены тем и
  оригинальное оформление; `task-controls/planner/board/preferences.css` —
  новые функциональные области. Остальные файлы обслуживают формы,
  рабочее пространство, файлы, поиск и анимацию.
- `build/offlineShell.ts` — локальные PDF-ресурсы и версионированная
  офлайн-оболочка; `securityHeaders.ts` — политика CSP для preview.

## Поток данных

Форма → проверенный черновик → операция → Web Lock → актуальный документ →
повтор намерений → проверка схемы → запись → обновлённое представление.
Ошибки записи сохраняют намерения в памяти и дают явную повторную попытку.

Основной ключ: `almis.focus.workspace.v4`. Старый ключ
`almis.focus.tasks.v1` остаётся нетронутым; перед миграцией создаётся
`almis.focus.tasks.before-v4`. Lock сохраняет имя прежнего протокола,
чтобы совместно сериализовать ещё открытые старые вкладки. Их последующие
записи обнаруживаются, но не заменяют v4.

Настройки и таймер: `almis.focus.planner.v1`, собственный Web Lock.
Вложения: IndexedDB `almis.focus.files`.
Журнал комментариев: `almis.focus.journal.v1`, отдельный Web Lock,
не более 500 записей по 4000 символов. `journalStorage` сохраняет полную
повреждённую строку до восстановления; `JournalLibrary` показывает записи
удалённых задач. `TaskWorkspace` связывает шаги, журнал, файлы и рисование.

Полная JSON-копия v6 включает журнал, все файлы, в том числе файлы удалённых задач,
настройки, историю и текущий таймер на паузе. ZIP v7 хранит тот же документ
в `focus.json`, а файлы — отдельными несжатыми потоковыми записями.
`workspaceArchive` проверяет схему, пути, число записей и CRC, `archiveReader`
ограничивает выделение памяти для каталога. Старые JSON-копии поддерживаются.
Импорт по ID не заменяет
существующие записи. Хранилища раздельные: при частичной ошибке preview
остаётся для безопасного повтора.

## Проверка и изменения

Node.js 22.13+. `npm ci --ignore-scripts`, `npm run typecheck`,
`npm test`, `npm run build`. 118 unit-тестов.
Браузерные проверки используют только свои вкладки и синтетические данные:
клавиатура и модальные окна, 320–1440 px, квота, повреждение, две вкладки,
полная копия, просмотр файлов, таймер, офлайн и смена версии.

Новый формат данных требует проверки миграции, отказа записи и повторения
операций. Идентификаторы и время готовятся до reducer. Не добавлять
побочные эффекты в reducer или React render. Изменения фокуса после
асинхронного действия выполняются после появления доступного элемента.

Текст — через React/pre, изображения — canvas, PDF — ограниченный canvas
с ленивой загрузкой PDF.js. CSV/TSV — ограниченная таблица; Office — текст из XML
без DOCTYPE, ссылок и активных объектов; ZIP — список записей без извлечения
на файловую систему. Медиа — локальные Blob URL с нативными controls.
Предпросмотр ограничен отдельно от сохранения оригинала; файлы ограничены
квотой устройства, до 100 вложений. Не добавлять HTML-вставку или активные preview.
Файлы не загружать на внешние сервисы. Не публиковать приватную переписку,
ключи, `.private/`, `.task/`, локальные контракты и служебные handoff-файлы.

## Публикация

`dist/` публикуется в отдельный каталог релиза собственного Nginx vhost,
затем переключается атомарная ссылка. Старый релиз сохраняется для отката.
Оболочка и manifest обновляются без длительного кеширования; хешированные
assets неизменяемы. Worker кеширует только разрешённые статические ресурсы,
сохраняет две предыдущие оболочки для открытых старых вкладок и не кеширует
задачи/файлы пользователя. Обновление не перезагружает открытый черновик.

Изменение типов ресурсов требует согласовать CSP preview и собственного
vhost. Поддержка PDF требует same-origin connect/worker; внешние origin,
фреймы и объекты запрещены. После публикации проверяются TLS/заголовки,
побайтовое соответствие сборке и реальные пользовательские действия.
Серверные checkpoints и доказательства остаются вне публичного Git.
